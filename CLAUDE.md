# Quickshell config

This is its own flake, separate from the `nix-refactor` flake. It owns its own
NixOS/home-manager modules (`nix/nixos.nix`, `nix/home-manager.nix`, exported
as `nixosModules.default`/`homeManagerModules.default`) — anything about
*running* quickshell (packages, the sway startup entry, bluetooth for the
control center, the `xdg.configFile` symlinks, the `programs.quickshell.*`
options) lives here, not in nix-refactor. nix-refactor imports those modules
as a flake input (`inputs.quickshell-config`) and only supplies the two values
it alone has: Stylix's theme (`programs.quickshell.theme`) and a host's chosen
ollama model (`programs.quickshell.ollamaChatModel`).

It's an immutable copy at runtime, not a live symlink — a QML edit here isn't
visible to the system bar until you commit, push, bump the input (`nix flake
lock --update-input quickshell-config` in nix-refactor), and `scripts/switch`.

For actually iterating on QML, don't touch the system bar: run `qs -p .` from
this directory in a separate terminal. That launches an independent,
hot-reloading instance straight from your working copy. One gap this leaves:
`theme.json`/`ask.json` are generated by `quickshell.nix` and only exist inside
the Nix-built config, not in this repo — if `Theme`/`OllamaConfig` need real
values under `qs -p .`, copy the live ones in once (`cp ~/.config/quickshell/{theme,ask}.json .`);
they're gitignored, so that's harmless and doesn't need redoing until Stylix's
colors or the ollama model change.

## Structure
- `shell.qml`: entry point. First line is `//@ pragma UseQApplication` (tray menus need it).
  It creates one `Bar` per screen with `Variants` over `Quickshell.screens`.
- Three directories, split by role. Each has its own `qmldir` — a missing line
  there shows up as "X is not a type". A file in one directory that uses a type
  from another needs `import "../components"` / `import "../services"` (same-directory
  types are visible without an import).
  - `components/`: dumb, reusable, stateless UI leaves (`BarItem`, `BarText`,
    `ThemedText`, `Divider`, `Island`, `SearchInput`). No singletons, no processes.
  - `services/`: the four singletons (`Theme`, `Stats`, `Dock`, `OllamaConfig`) plus
    `RestartableProcess`, a small process-restart helper they rely on.
  - `modules/`: composed feature widgets — one per bar feature (`Bar`, `Left`,
    `Center`, `Right`, `Clock`, `Volume`, `Tray`, `WindowTitle`, `Workspaces`,
    `Equalizer`, `Toast`, `Launcher`, `AskOllama`) plus `cava.conf`.
  A new file goes in whichever of the three matches its role, plus a line in that
  directory's `qmldir`.
- `Bar.qml` is a transparent `PanelWindow` holding three regions: `Left`,
  `Center`, `Right`. A `mask` Region limits clicks to them. `Center` is the
  dynamic island itself — a single bordered `Rectangle` that shows the
  `Equalizer` at idle and grows in place (animated width/height) to host
  whatever `Dock.mode` loads (`Toast`/`Launcher`/`AskOllama`). The bar's
  `implicitHeight` tracks `center.height`, but `exclusiveZone` stays pinned
  to the slim row height, so the expansion floats over windows below instead
  of pushing them down.
- `Dock.qml` is a singleton that owns all dynamic-island state: `mode`
  (`idle`/`toast`/`launcher`/`ask`), the ambient toast queue (notifications,
  volume), and the `IpcHandler`s sway keybinds call into
  (`quickshell ipc call launcher open`, `quickshell ipc call ask open`).
  Notification content comes from quickshell's own `NotificationServer`
  (`services/NotificationWatcher.qml`) — quickshell is the DBus
  notification daemon, there's no swaync or other daemon underneath.
- `Stats.qml` is a singleton that owns all polling (CPU, RAM, GPU, VRAM).
  Modules display its values and never poll on their own.
- `theme.json` and `ask.json` are generated by `nix/home-manager.nix` from
  `programs.quickshell.theme`/`programs.quickshell.ollamaChatModel` (values
  nix-refactor sets from Stylix and host config) and read by
  `services/Theme.qml` / `services/OllamaConfig.qml`. Both are gitignored.
  Never edit or commit them.
- `nix/`: this flake's two module outputs. Nothing QML-related belongs here;
  nothing Stylix/host-specific belongs here either — those stay options that
  nix-refactor sets.

## Rules
- Colors and fonts come only from the `Theme` singleton. No hex values, no font names.
- Bar/dock sizing constants (e.g. row height) come from `Theme` too — don't
  re-hardcode a size that's meant to be shared across files.
- Never name a singleton `Color` (it collides with a built-in type).
- Use `font.pointSize`, not `pixelSize`. Stylix sizes are points.
- Files that use QtQuick types (`color`, `Item`, ...) need `import QtQuick`.
- Delegates use `required property var modelData`.
- Look: sharp corners, 1px `Theme.border` outlines, text only. Tray icons are
  the only exception. Right-side modules are `BarText`, which draws its own
  left divider.

## Verifying
- Run `qs -p .` from this directory and read the first `ERROR`/`WARN` line.
  Property mistakes often only warn, so a broken bar can vanish without an
  error screen.
- Check type and property names against the Quickshell docs for the installed version
  (`quickshell --version`, then https://quickshell.org/docs). Never rely on memory
  for API names.
